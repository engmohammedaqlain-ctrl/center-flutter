# نسخة التطبيق لكل مدرسة

## الفكرة
- مع كل إصدار تُرفع نسخة لكل مدرسة باسم `center-<الإصدار>-<الكود>.apk`.
- أيقونة هذه النسخة شعار المدرسة، وكود المدرسة مكتوب داخلها.
- اسم التطبيق على الشاشة واحد لكل المدارس: «النظام المدرسي».
- لا يُعاد بناء التطبيق لكل مدرسة. السكربت يأخذ الملف الذي بناه Shorebird، ويبدّل الأيقونة، ويكتب الكود، ثم يوقّعه بمفتاح التطبيق نفسه.
- صفحة المدرسة `/d/<الكود>` تعطي ولي الأمر نسخة مدرسته.
- التطبيق يعرض اسم المدرسة وشعارها من أول فتح، قبل تسجيل الدخول.
- التحديث داخل التطبيق ينزّل نسخة مدرسة الجهاز، فتبقى أيقونتها بعد التحديث.

## الحالة
| الجزء | الحالة |
|---|---|
| الكود | مكتوب، والفحص (`dart analyze`) بلا أخطاء |
| تبديل الأيقونة في ملف التطبيق المنشور (2.2) | نجح |
| التوقيع والتثبيت على جوال | **لم يُختبر** |
| تحديثات Shorebird الصامتة على نسخة مدرسة | **لم يُختبر** |

## النشر
```
DEV_USERNAME=... DEV_PASSWORD=... dart run tool/publish_release.dart --notes "..."
```
- بدون حساب المطور، اكتب المدارس بنفسك: `--schools ABC,DEF`.
- للنشر بلا نسخ مدارس: `--no-schools`. انتبه: أجهزة المدارس ستتحدّث حينها إلى الأيقونة العامة.
- لمدرسة جديدة بعد آخر نشر: `--add-schools ABC`، أو `--add-schools all` لكل مدرسة ليست لها نسخة.
- المدرسة التي شعارها SVG تأخذ الأيقونة العامة. الصيغ المدعومة للشعار: PNG وJPEG وWebP.

## الاختبار المطلوب (عند زميلك)
1. نشر تجريبي: `--dry-run --schools <كود>`، ثم تثبيت `build/release/center-*-<كود>.apk` على جوال.
2. التحقق من ثلاثة أشياء:
   - الأيقونة هي شعار المدرسة.
   - شاشة الدخول تعرض اسم المدرسة.
   - التطبيق يُفتح ويعمل.
3. نشر تحديث صامت تجريبي، والتحقق أنه وصل إلى نسخة المدرسة.
4. تثبيت نسخة المدرسة فوق النسخة العامة، والتأكد أن التحديث يُقبل بلا حذف التطبيق.

## الملفات
- `tool/school_apk.dart`: يصنع نسخة المدرسة.
- `tool/publish_release.dart`: يبني نسخ المدارس ويرفعها.
- `assets/school.json`: كود المدرسة، وفي النسخة العامة `{}`.
- `lib/data/school_brand.dart`: قراءة الكود، واسم المدرسة وشعارها.
- `lib/data/app_update.dart`: اختيار نسخة المدرسة عند التحديث.
- مشروع الويب `functions/d/[[path]].ts`: رابط أندرويد لكل مدرسة.
